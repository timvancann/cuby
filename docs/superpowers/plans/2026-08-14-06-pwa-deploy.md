# PWA & GitHub Pages Deploy Plan

> Executed inline (ops-heavy, environment-coupled). Spec: cube-trainer-spec.md §6.2, §4.3 (offline), §8.

**Goal:** Public GitHub repo `cuby`, installable offline-capable PWA on GitHub Pages, deployed on every push to main.

Steps:

1. **Icon**: `tools/gen-icon.ts` generates `public/icon.svg` from the same perspective-cube math as the mode card (committed, reproducible). PNG renders (512, 192 maskable-safe, 180 apple-touch) rasterized once via headless browser, committed under `public/`. Favicon links in `index.html`.
2. **PWA**: `vite-plugin-pwa` — `registerType: 'prompt'`, manifest (name Cuby, standalone, theme/background `#101114`, icons), workbox precaching all built assets incl. the large lazy cubing/three chunks (`maximumFileSizeToCacheInBytes` raised). A small update toast in App.svelte ("update available → reload") per §6.2's discreet prompt. `virtual:pwa-register` types via vite-env reference.
3. **Deploy workflow**: extend `.github/workflows/ci.yml` with a `deploy` job (needs test job; `actions/configure-pages` with `enablement: true`, `upload-pages-artifact` of `dist/`, `deploy-pages`), Pages permissions + concurrency, push-to-main only.
4. **Repo**: `gh repo create cuby --public`, push main; verify the workflow run and the live URL.
5. **Verification**: live URL loads on the Pages path (relative `base: './'` + hash routing require no path config); service worker registered; offline reload works including Timer scramble generation and the animator (precached chunks) via headless browser with network disabled.

Base-path note: the app uses `base: './'` and hash routing throughout, so it is path-agnostic — no `/cuby/` hardcoding anywhere.
